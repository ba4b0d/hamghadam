## 1. Google OAuth 2.0 & Firebase Project Configuration

### 1.1 Overview & Architecture
HamGhadam uses Google Sign-In on Android to obtain a Google ID Token (`JWT`), which is sent to the FastAPI backend (`POST /api/v1/auth/google`). The backend verifies the token using Google's public keys via the `google-auth` Python library and returns a native HamGhadam Bearer JWT access token.

### 1.3 Backend Token Verification & Account Linking Flow
- **Endpoint**: `POST /api/v1/auth/google`
- **Request Body**: `{ "id_token": "eyJhbGci..." }`
- **Python Library**: `google-auth` (`pip install google-auth requests`)
- **Backend Verification Logic**:
  ```python
  from google.oauth2 import id_token
  from google.auth.transport import requests
  
  try:
      id_info = id_token.verify_oauth2_token(
          token_payload.id_token,
          requests.Request(),
          audience=settings.google_web_client_id
      )
  except ValueError as e:
      raise HTTPException(status_code=401, detail="Invalid Google ID token")
  
  google_id = id_info["sub"]
  email = id_info.get("email", "").lower()
  email_verified = id_info.get("email_verified", False)
  name = id_info.get("name")
  picture_url = id_info.get("picture")
  ```
- **Upsert / Link Logic**:
  1. Check `email_verified`: if False, raise `HTTP 400 Bad Request` ("Unverified Google email").
  2. Query `User` by `google_id == google_id`.
  3. If user found: return JWT for this user.
  4. If user not found by `google_id`, query `User` by `email == email`:
     - If existing email user found: link account by setting `user.google_id = google_id`, update `avatar_url = user.avatar_url or picture_url`, set `auth_provider = "google"`. Commit and return JWT.
  5. If user not found at all: create new `User`:
     - `email = email`
     - `password_hash = hash_password(secrets.token_urlsafe(32))` (random unusable hash)
     - `display_name = name or email.split('@')[0]`
     - `google_id = google_id`
     - `avatar_url = picture_url`
     - `auth_provider = "google"`
     - Commit and return JWT.

## 2. Avatar Storage & Static Serving Architecture on RP5

### 2.1 File Path & Directory Layout on Raspberry Pi 5
- **Host Path**: `/var/www/hamghadam/avatars/`
- **Permissions**: Owner `www-data` or app user (`ba4b0d`), mode `0755` (`chmod 755 /var/www/hamghadam/avatars/`).
- **Docker Compose Integration**:
  - Service container volume mount:
    ```yaml
    volumes:
      - /var/www/hamghadam/avatars:/app/static/avatars
    ```

### 2.2 Nginx Proxy Manager (NPM) / Nginx Configuration
- **Public Domain**: `https://api.hamghadam.ba4b0d.ir`
- **Avatar Serving URL**: `https://api.hamghadam.ba4b0d.ir/static/avatars/{uuid}.{ext}`
- **Nginx Custom Location Configuration** (in NPM Custom Nginx Configuration tab for `api.hamghadam.ba4b0d.ir`):
  ```nginx
  # Maximum file upload limit for avatar endpoint
  client_max_body_size 5M;

  location /static/avatars/ {
      alias /var/www/hamghadam/avatars/;
      expires 30d;
      add_header Cache-Control "public, max-age=2592000, no-transform";
      add_header X-Content-Type-Options "nosniff";
      add_header Access-Control-Allow-Origin "*";
      
      # Security: Disable execution of CGI/script extensions
      location ~ \.(php|py|sh|pl|cgi|exe)$ {
          deny all;
      }
  }
  ```

### 2.3 Security, Validation & Sanitization Pipeline
When processing avatar uploads in `POST /api/v1/users/me/avatar`:
1. **Size Limit Enforcement**:
   - Limit `UploadFile` to 5MB (5,242,880 bytes).
2. **MIME Type & Content Header Verification**:
   - Allowed MIME Types: `image/jpeg`, `image/png`, `image/webp`.
   - Perform binary header inspection (e.g. using `PIL.Image.open(file.file)` or magic bytes checking: `\xFF\xD8\xFF` for JPEG, `\x89PNG` for PNG, `RIFF...WEBP` for WebP). Reject unparseable or spoofed files with HTTP 400.
3. **Filename Sanitization & Prevention of Overwrites/Traversal**:
   - Strip client-supplied filename completely.
   - Generate secure UUID v4 filename: `avatar_id = str(uuid.uuid4())`.
   - Target filename: `{avatar_id}.{extension}` (e.g., `3f2504e0-4f89-4113-a40f-080027607912.webp` or `.jpg`).
4. **Storage & URL Generation**:
   - Save file to `/app/static/avatars/{filename}`.
   - Construct absolute URL: `https://api.hamghadam.ba4b0d.ir/static/avatars/{filename}`.
   - Update `user.avatar_url = url` in database.

#### New `friendships` Table Schema
```python
# app/models/friendship.py
import enum
from datetime import datetime
from sqlalchemy import Integer, String, DateTime, ForeignKey, UniqueConstraint, CheckConstraint, Enum, Index, func
from sqlalchemy.orm import Mapped, mapped_column, relationship
from app.core.database import Base

class FriendshipStatus(str, enum.Enum):
    PENDING = "PENDING"
    ACCEPTED = "ACCEPTED"
    REJECTED = "REJECTED"
    BLOCKED = "BLOCKED"

class Friendship(Base):
    __tablename__ = "friendships"

    id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True)
    requester_id: Mapped[int] = mapped_column(Integer, ForeignKey("users.id", ondelete="CASCADE"), nullable=False, index=True)
    addressee_id: Mapped[int] = mapped_column(Integer, ForeignKey("users.id", ondelete="CASCADE"), nullable=False, index=True)
    status: Mapped[FriendshipStatus] = mapped_column(
        Enum(FriendshipStatus, name="friendship_status_enum", native_enum=False),
        default=FriendshipStatus.PENDING,
        nullable=False
    )
    created_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now(), nullable=False)
    updated_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now(), onupdate=func.now(), nullable=False)

    requester: Mapped["User"] = relationship("User", foreign_keys=[requester_id], backref="sent_friendships")
    addressee: Mapped["User"] = relationship("User", foreign_keys=[addressee_id], backref="received_friendships")

    __table_args__ = (
        UniqueConstraint("requester_id", "addressee_id", name="uq_friendship_requester_addressee"),
        CheckConstraint("requester_id != addressee_id", name="ck_friendship_no_self"),
        Index("idx_friendships_requester_status", "requester_id", "status"),
        Index("idx_friendships_addressee_status", "addressee_id", "status"),
    )
```

### 3.2 Bidirectional Friendship Query Pattern & Anti-Duplication
To determine if User A and User B are friends regardless of who initiated:
```python
stmt = select(Friendship).where(
    or_(
        and_(Friendship.requester_id == user_a_id, Friendship.addressee_id == user_b_id),
        and_(Friendship.requester_id == user_b_id, Friendship.addressee_id == user_a_id)
    )
)
```
When creating a friend request, ensure ordering or check reverse relationship before inserting to prevent A->B and B->A duplicate rows:
```python
existing = db.scalar(stmt)
if existing:
    if existing.status == FriendshipStatus.ACCEPTED:
        raise HTTPException(400, "Already friends")
    elif existing.status == FriendshipStatus.PENDING:
        raise HTTPException(400, "Friend request already pending")
```

### 3.3 OpenAPI Endpoint Specifications

#### Auth & User Endpoints
1. `POST /api/v1/auth/google`
   - **Request**: `{ "id_token": "string" }`
   - **Response 200**: `TokenResponse` (`access_token`, `token_type`, `user`)
2. `PATCH /api/v1/users/me`
   - **Request**: `{ "display_name": "string", "bio": "string", "tz_offset": int }`
   - **Response 200**: `UserOut`
3. `POST /api/v1/users/me/avatar`
   - **Content-Type**: `multipart/form-data`
   - **Request**: `file: UploadFile`
   - **Response 200**: `{ "avatar_url": "https://api.hamghadam.ba4b0d.ir/static/avatars/uuid.jpg" }`
4. `GET /api/v1/users/search?q={query}`
   - **Query**: `q` (min 2 chars)
   - **Response 200**: `list[UserPublicOut]` with schema:
     `id`, `display_name`, `avatar_url`, `bio`, `friendship_status` (`NONE`, `PENDING_SENT`, `PENDING_RECEIVED`, `ACCEPTED`, `BLOCKED`)

#### Friend Network Endpoints
5. `POST /api/v1/friends/request`
   - **Request**: `{ "addressee_id": int }`
   - **Response 201**: `FriendshipOut` (`id`, `requester_id`, `addressee_id`, `status`, `created_at`)
6. `POST /api/v1/friends/accept/{request_id}`
   - **Path**: `request_id` (ID of the friendship record where current user is `addressee_id`)
   - **Response 200**: `FriendshipOut` (status set to `ACCEPTED`)
7. `POST /api/v1/friends/reject/{request_id}`
   - **Path**: `request_id`
   - **Response 200**: `FriendshipOut` (status set to `REJECTED` or deleted)
8. `DELETE /api/v1/friends/{friend_user_id}`
   - **Path**: `friend_user_id` (User ID of the friend to remove)
   - **Response 204**: No Content (deletes friendship record)
9. `GET /api/v1/friends`
   - **Response 200**: `list[FriendProfileOut]` (`id`, `email`, `display_name`, `avatar_url`, `bio`, `today_steps`)
10. `GET /api/v1/friends/requests/pending`
    - **Response 200**: `list[PendingRequestOut]` (`request_id`, `requester`: `UserPublicOut`, `created_at`)

### 4.2 Account & Data Deletion Compliance (Mandatory Play Policy)
Google Play policy requires all apps offering account creation to allow users to delete their account both in-app and on a web page:
1. **In-App Deletion**:
   - Backend endpoint: `DELETE /api/v1/users/me`
   - Deletes user record, avatars, friendships, devices, and health scores (or anonymizes data).
2. **Web URL Deletion Request Page**:
   - Hosting a static page at `https://hamghadam.ba4b0d.ir/privacy/delete-account` with a web form or email contact mechanism (`delete-my-account@hamghadam.ba4b0d.ir`).
