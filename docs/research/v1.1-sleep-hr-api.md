# Health Connect V1.1 Integration: Sleep & Heart Rate Read APIs, Watch Sync Characteristics, and Play Console Declaration

## Executive Summary

This research report documents the technical specifications, Kotlin API usage patterns, watch data synchronization characteristics, and Google Play Console compliance requirements for integrating **Heart Rate** (`HeartRateRecord`) and **Sleep** (`SleepSessionRecord`) metrics into **HamGhadam** (V1.1).

Per the V1.1 scope decision, HamGhadam operates as a **phone-only Android application** that reads health data written into Health Connect by ecosystem companion apps (Samsung Health, Fitbit/Google Fit, Nothing X) or phone sensors.

---

## 1. Health Connect Read & Aggregation APIs (`androidx.health.connect.client`)

HamGhadam utilizes the AndroidX Health Connect Jetpack library (`androidx.health.connect:connect-client:1.1.0-alpha10` or stable equivalent) [1].

### 1.2 Heart Rate API (`HeartRateRecord`)

`HeartRateRecord` captures series of heart rate samples over time intervals [3]. Each record contains a list of `HeartRateRecord.Sample` objects with timestamps and Beats-Per-Minute (`bpm`) values.

#### 1.2.1 Reading Raw Heart Rate Records
```kotlin
import androidx.health.connect.client.HealthConnectClient
import androidx.health.connect.client.records.HeartRateRecord
import androidx.health.connect.client.request.ReadRecordsRequest
import androidx.health.connect.client.time.TimeRangeFilter
import java.time.Instant

suspend fun readHeartRateRaw(
    healthConnectClient: HealthConnectClient,
    startTime: Instant,
    endTime: Instant
): List<HeartRateRecord> {
    val response = healthConnectClient.readRecords(
        ReadRecordsRequest(
            recordType = HeartRateRecord::class,
            timeRangeFilter = TimeRangeFilter.between(startTime, endTime)
        )
    )
    return response.records
}
```

#### 1.2.2 Statistical Aggregation (`BPM_AVG`, `BPM_MIN`, `BPM_MAX`)
Health Connect provides built-in metrics for statistical aggregation over specified time windows [2][3]:
- `HeartRateRecord.BPM_AVG`: Average beats per minute across the range.
- `HeartRateRecord.BPM_MIN`: Minimum recorded heart rate.
- `HeartRateRecord.BPM_MAX`: Maximum recorded heart rate.
- `HeartRateRecord.MEASUREMENTS_COUNT`: Total count of individual heart rate samples.

```kotlin
import androidx.health.connect.client.request.AggregateRequest

data class HeartRateSummary(
    val avgBpm: Long,
    val minBpm: Long,
    val maxBpm: Long,
    val measurementCount: Long
)

suspend fun readHeartRateSummary(
    healthConnectClient: HealthConnectClient,
    startTime: Instant,
    endTime: Instant
): HeartRateSummary {
    val response = healthConnectClient.aggregate(
        AggregateRequest(
            metrics = setOf(
                HeartRateRecord.BPM_AVG,
                HeartRateRecord.BPM_MIN,
                HeartRateRecord.BPM_MAX,
                HeartRateRecord.MEASUREMENTS_COUNT
            ),
            timeRangeFilter = TimeRangeFilter.between(startTime, endTime)
        )
    )
    
    return HeartRateSummary(
        avgBpm = response[HeartRateRecord.BPM_AVG] ?: 0L,
        minBpm = response[HeartRateRecord.BPM_MIN] ?: 0L,
        maxBpm = response[HeartRateRecord.BPM_MAX] ?: 0L,
        measurementCount = response[HeartRateRecord.MEASUREMENTS_COUNT] ?: 0L
    )
}
```

### 1.3 Sleep API (`SleepSessionRecord`)

`SleepSessionRecord` represents an overall sleep session duration along with optional granular sleep stage breakdowns (`SleepStage`) such as Light, Deep, REM, and Awake [4].

#### 1.3.1 Reading Raw Sleep Sessions & Stages
```kotlin
import androidx.health.connect.client.records.SleepSessionRecord

suspend fun readSleepSessions(
    healthConnectClient: HealthConnectClient,
    startTime: Instant,
    endTime: Instant
): List<SleepSessionRecord> {
    val response = healthConnectClient.readRecords(
        ReadRecordsRequest(
            recordType = SleepSessionRecord::class,
            timeRangeFilter = TimeRangeFilter.between(startTime, endTime)
        )
    )
    return response.records
}
```

#### 1.3.2 Aggregate Sleep Duration (`SLEEP_DURATION_TOTAL`)
Health Connect aggregates cumulative sleep session time via `SleepSessionRecord.SLEEP_DURATION_TOTAL` [2][4]:

```kotlin
import java.time.Duration

suspend fun readTotalSleepDuration(
    healthConnectClient: HealthConnectClient,
    startTime: Instant,
    endTime: Instant
): Duration {
    val response = healthConnectClient.aggregate(
        AggregateRequest(
            metrics = setOf(SleepSessionRecord.SLEEP_DURATION_TOTAL),
            timeRangeFilter = TimeRangeFilter.between(startTime, endTime)
        )
    )
    return response[SleepSessionRecord.SLEEP_DURATION_TOTAL] ?: Duration.ZERO
}
```

## 2. OEM Watch Sync Characteristics & Caveats

Because HamGhadam does not run a standalone Wear OS app in V1.1, heart rate and sleep records rely on external companion apps writing data into Health Connect. Sync frequencies and mechanisms differ by manufacturer.

| OEM / Device Ecosystem | Data Flow Path | Heart Rate Sync Behavior | Sleep Data Sync Behavior |
| :--- | :--- | :--- | :--- |
| **Samsung Galaxy Watch** (Watch 4/5/6/7) | Watch → Samsung Health → Health Connect | **Continuous HR**: Lazy background sync (batched every 15–60 min or on phone unlock) to conserve battery [5]. <br>**Manual HR**: Immediate sync [5]. | Written in batch upon morning sleep session resolution (wake detection). |
| **Google Pixel Watch** (Watch 1/2/3) | Watch → Fitbit App → Health Connect | **Continuous HR**: Batched sync every 15–30 min via Fitbit app background sync. <br>**Resting HR**: Daily aggregated resting HR record written once daily. | Written in batch shortly after morning Fitbit sync. |
| **Nothing / CMF Watch** (CMF Watch Pro / RTOS) | Watch → Nothing X / CMF App → Health Connect | **Continuous HR**: Dependent on companion app background sync permissions. Periodic sampling (5–10 min interval) unless active GPS workout is enabled. | Written upon companion app synchronization after wake-up. |

### Technical Takeaways for HamGhadam Android Sync:
1. **Background Pull Timing**: Daily synchronization (`DailySyncWorker`) should execute during low-activity windows (e.g. 06:00–08:00 AM) or upon app launch to ensure third-party watch companion apps have completed their morning batch sync.
2. **Missing Sample Handling**: If continuous HR measurements are sparse or delayed from lazy sync, HamGhadam uses `HeartRateRecord.BPM_AVG` over available valid samples rather than assuming 0 BPM.

## 3. Google Play Console Compliance & Health Apps Declaration

### 3.1 Play Policy Requirements
Under Google Play Developer Policy for Health Connect & Health Apps [6][7]:
1. **Health Apps Declaration Form**: Must be completed in Google Play Console under **Policy > App content > Health apps declaration**.
2. **Approved Category & Use Case**: HamGhadam declares access under **Fitness & Wellness Tracking** and **Peer Challenges**.
3. **Data Safety Disclosure**: Declare that `READ_HEART_RATE` and `READ_SLEEP` are collected solely for in-app metrics and challenge scoring, encrypted in transit (HTTPS/TLS), and never sold or shared with ad networks.

---

### 3.2 Required Android Manifest Activity & Alias Declarations

Google Play requires apps requesting Health Connect permissions to expose a rationale activity so users clicking "Privacy Policy" inside Health Connect settings are directed to the app's privacy rationale [1].

```xml
<application>
    <!-- Privacy Rationale Activity for Android 13 and below -->
    <activity
        android:name=".ui.permissions.PermissionsRationaleActivity"
        android:exported="true">
        <intent-filter>
            <action android:name="androidx.health.ACTION_SHOW_PERMISSIONS_RATIONALE" />
        </intent-filter>
    </activity>

    <!-- Activity Alias for Android 14+ Health Permission Rationale -->
    <activity-alias
        android:name="ViewPermissionUsageActivity"
        android:exported="true"
        android:targetActivity=".ui.permissions.PermissionsRationaleActivity"
        android:permission="android.permission.START_VIEW_PERMISSION_USAGE">
        <intent-filter>
            <action android:name="android.intent.action.VIEW_PERMISSION_USAGE" />
            <category android:name="android.intent.category.HEALTH_PERMISSIONS" />
        </intent-filter>
    </activity-alias>
</application>
```
