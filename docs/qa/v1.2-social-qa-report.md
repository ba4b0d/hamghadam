## 2. Google Sign-In & Account Linking Verification

### Test Scenarios & Results
1. **New User Registration via Google OAuth**:
   - **Request**: `POST /api/v1/auth/google` with mock Google ID token (`sub="google-user-12345"`, `email="google_new@example.com"`, `name="Google New User"`).
   - **Result**: `200 OK`. Access token issued, user record created with `auth_provider="google"`, `avatar_url` set to Google profile picture.
2. **Account Linking (Matching Existing Email/Password Account)**:
   - **Request**: User registered via email `linking_user@example.com`. Subsequent `POST /api/v1/auth/google` called with matching verified Google email.
   - **Result**: `200 OK`. Existing user record linked (`user.google_id` set, `auth_provider="google"`), existing user ID preserved.
3. **Unverified Google Email Rejection**:
   - **Request**: `POST /api/v1/auth/google` with `email_verified=False`.
   - **Result**: `400 Bad Request` ("Unverified Google email").
4. **Invalid / Expired ID Token**:
   - **Request**: `POST /api/v1/auth/google` with invalid token signature.
   - **Result**: `401 Unauthorized` ("Invalid Google ID token").

## 3. Profile & Avatar Upload E2E Verification

### Test Scenarios & Results
1. **Bio & Profile Information Update**:
   - **Request**: `PATCH /api/v1/users/me/bio` (`{"bio": "Marathon enthusiast & tech lead"}`) and `PATCH /api/v1/users/me` (`{"display_name": "Barbad Runner", "location": "Tehran", "tz_offset": 210}`).
   - **Result**: `200 OK`. Profile data stored and confirmed via subsequent `GET /api/v1/users/me`.
2. **Multipart Avatar Upload**:
   - **Request**: `POST /api/v1/users/me/avatar` with `multipart/form-data` image file (`JPEG`, `PNG`, `WEBP`).
   - **Result**: `200 OK`. File binary headers validated, saved with UUID v4 filename (`/app/static/avatars/<uuid>.<ext>`), returning URL `https://api.hamghadam.ba4b0d.ir/static/avatars/<uuid>.<ext>`.
3. **Static File Serving & Security**:
   - **Verification**: `GET /static/avatars/<filename>` and `GET /avatars/<filename>` both return HTTP 200 with raw image bytes.
   - **Security Checks**: MIME type restriction (non-image files like `text/plain` rejected with `400 Bad Request`), corrupted image binaries rejected with `400 Bad Request`, size limit (>5MB) rejected with `400 Bad Request`.
4. **Account & Avatar Data Deletion**:
   - **Request**: `DELETE /api/v1/users/me`.
   - **Result**: `204 No Content`. Purges user record, avatar files, and social friendships. Subsequent requests using bearer token return `401 Unauthorized`.

## 4. Friends Lifecycle Multi-Account Verification

### End-to-End Multi-Account Flow Step-by-Step
1. **User Search**:
   - **Action**: User A (`qa_user_a@example.com`) queries `/api/v1/users/search?q=User B`.
   - **Result**: `200 OK`. Returns User B with `friendship_status="NONE"`. (Self is excluded from search results).
2. **Friend Request Creation**:
   - **Action**: User A calls `POST /api/v1/friends/request` (`{"target_user_id": <id_b>}`).
   - **Result**: `201 Created`. Friendship created with `status="PENDING"`.
3. **Friendship Status & Pending Request Notification**:
   - **Action**: User A's search for User B shows `friendship_status="PENDING_SENT"`. User B's search for User A shows `friendship_status="PENDING_RECEIVED"`.
   - **Action**: User B calls `GET /api/v1/friends/requests/pending`.
   - **Result**: `200 OK`. User B receives pending request list with User A's public profile and request ID.
4. **Friend Request Acceptance**:
   - **Action**: User B calls `POST /api/v1/friends/accept/{request_id}`. (User C attempting to accept returns `403 Forbidden`).
   - **Result**: `200 OK`. Friendship updated to `status="ACCEPTED"`.
5. **Bidirectional Friends List & Step Counts**:
   - **Action**: User B ingests 8,500 steps for today via `POST /api/v1/daily/ingest`.
   - **Action**: Both User A and User B query `GET /api/v1/friends`.
   - **Result**: `200 OK`. User A sees User B in friends list with `today_steps=8500`. User B sees User A.
6. **Duplicate & Anti-Self Validation**:
   - Sending request to self returns `400 Bad Request` ("Cannot send friend request to yourself").
   - Sending duplicate request to existing pending friend returns `400 Bad Request` ("Friend request already pending").
7. **Friend Removal**:
   - **Action**: User A calls `DELETE /api/v1/friends/{id_b}`.
   - **Result**: `204 No Content`. Friendship record removed; subsequent `GET /api/v1/friends` for both users returns empty list `[]`.
